Eke turns binary layouts into small, composable schemas. Define how bytes are
decoded, compose those definitions into application values, and retain the
inferred TypeScript type throughout.

```ts
import { bytes, struct, u8, u16 } from "@marceloclp/eke";
import type { Infer } from "@marceloclp/eke";

const message = struct({
    version: u8().is(1),
    body: bytes(u16()).utf8(),
});

type Message = Infer<typeof message>;

const value: Message = message.decode(Uint8Array.of(1, 2, 0, 0x6f, 0x6b));
// { version: 1, body: "ok" }
```

All built-in numeric decoders are little-endian. A top-level `decode()` succeeds
only when it consumes the complete input. Truncation, unexpected trailing
bytes, and validation failures throw `DecodeError` with a byte offset and path.

## Why Eke

- **Composable schemas.** Reuse primitives in arrays, structs, frames, unions,
  and runtime-selected layouts.
- **Precise types.** `Infer` preserves literal checks, bigint widths, nested
  structs, and transformed values.
- **Contextual failures.** `DecodeError` identifies both the byte offset and the
  nested field or array index.
- **Open decoder state.** `BsdReader` exposes its cursor, active frame, path,
  input views, and low-level readers for specialized binary formats.
- **Portable runtime.** The package is ESM-only, dependency-free, and operates
  on `Uint8Array` without Node-specific APIs.

## Naming

Public schema interfaces use the `Bsd` prefix, short for **binary schema
decoder**: `BsdSchema`, `BsdNumber`, `BsdBytes`, and `BsdStruct`. Constructors
stay concise (`u16()`, `bytes()`, `struct()`) because they are the API used most
often when declaring a layout.
